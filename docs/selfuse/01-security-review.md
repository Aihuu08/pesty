# 阶段 1：安全审查报告

- 范围：`Sources/Pesty` 全部 37 个文件（7,123 行），以及 `Package.swift`、`scripts/`、`.github/`、`packaging/`
- 基线：上游 1.3.0（提交 `b3f7798`）
- 方法：逐文件读代码，并用 grep 交叉核对。审查在 Linux 容器中完成，**所有结论都没有在 macOS 上运行过**。标「读码确认」的条目，是代码路径本身已经能说明问题；标「未验证」的条目，必须在 Mac 上实测才能下结论。
- 复现测试：`Tests/PestyTests/Phase1ReproTests.swift`，只能在 macOS 上跑（CI 或本机 `swift test`）。

## 一、结论（给不看细节的人）

**可以自用。** 没有发现后门、遥测、远程代码执行，或者把剪贴板内容发到网络的代码。
有几处需要修，或者在修好之前需要留意：

1. 打开「通过 iCloud Drive 同步」之前，先等阶段 3 的修复。这个功能有 3 个问题：删除的条目会复活、本机保存一次后监听就失效、可能被利用来删除文件。不开这个功能就不受影响（默认是关闭的）。
2. 在 Mac 上验证完之前，**先别用右键菜单里的「清除格式粘贴」和「粘贴为 Markdown」**。这两项会调用系统的 HTML 解析器，可能去加载网页里的远程图片（未验证）。
3. 如果 store.json 损坏，下一次保存会用空历史把它覆盖，历史就丢了（读码确认）。阶段 4 安装前的备份步骤就是为了防这个。

## 四、对你 5 条假设的验证

| 假设 | 结论 | 说明 |
|---|---|---|
| 1. 合并是并集，删除会复活 | **成立** | 见 D。另外发现 merge 没有应用排除 App 过滤 |
| 2. 监听在第一次保存后失效 | **成立（读码）** | 见 E。复现测试证明的是底层机制：原子写入之后，没有重新挂载的 vnode 监听收不到后续事件。完整的端到端行为需要两台 Mac，**未验证** |
| 3. 搜索只有 lowercased().contains | **成立** | 而且是每次访问都对全量历史重新拼接字符串（`ClipItem.searchableText` 是计算属性），一次界面刷新会访问 `visibleItems` 好几次 |

## 五、构建链（Package.swift、scripts/、.github/）

- `Package.swift`：没有任何依赖。唯一的特殊设置是 `unsafeFlags(["-parse-as-library"])`，用来支持可执行目标里的 `@main`，无害。
- `scripts/build_app.sh`：本地 `swift build`、生成图标、组装 .app、ad-hoc 签名（见 G），没有网络操作。
- `scripts/make_icon.sh` 和 `IconGen.swift`：在本机用 AppKit 画图标，调用 `sips` 和 `iconutil`，无害。
- `sign_notarize.sh`、`release_build.sh`、`build_mas.sh`：使用原作者的签名身份，按你的要求**没有运行**。
- `.github/workflows/release.yml`：只能手动触发，需要 secrets，不会自动运行。
- `.github/workflows/ci.yml`：第三方 action `maxim-lobanov/setup-xcode@v1` 只固定到了大版本标签，没有固定到提交 SHA，属于供应链风险。这只影响 CI，不影响你本机编译出来的产物。
- **纠正一处背景信息**：`BarWindowController` 在 `#available(macOS 26.0, *)` 分支里用了 `NSGlassEffectView`，所以编译需要 **Xcode 26 以上的 SDK**，Xcode 16 编不过。上游 CI 用的是 Xcode 26.3。
